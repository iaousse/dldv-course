AstuceObjectifs du chapitre

À la fin de ce chapitre, l’étudiant sera capable de :

  • Expliquer pourquoi une organisation sépare souvent les systèmes opérationnels des données destinées à l’analyse ;
  • Distinguer une base transactionnelle, un entrepôt de données, un lac de données et un datamart ;
  • Lire un modèle en étoile composé d’une table de faits et de tables de dimensions ;
  • Définir le grain d’une table de faits et choisir des mesures adaptées ;
  • Décrire les grandes étapes d’un flux ETL/ELT, de la source au tableau de bord.

Un tableau de bord fiable ne commence pas par un graphique. Il commence par des données organisées, documentées et mises à jour de façon régulière. L’entrepôt de données (data warehouse) fournit cette base pour l’analyse.

1. Pourquoi un entrepôt de données ?

1.1. Les systèmes opérationnels

Une application de vente, une caisse ou un site web utilise une base opérationnelle pour enregistrer les événements du quotidien : créer une commande, modifier une adresse, enregistrer un paiement. Ces systèmes doivent répondre vite à de petites opérations et éviter les incohérences.

Une base opérationnelle est souvent organisée pour limiter la répétition des informations. Une commande peut être répartie entre clients, commandes et lignes_commande, reliées par des identifiants.

Cette organisation est adaptée à l’écriture, mais une question analytique comme « Quel est le chiffre d’affaires mensuel par région et par catégorie depuis trois ans ? » peut nécessiter de nombreuses jointures et plusieurs sources. Exécuter ce type de requête directement sur la base de production peut ralentir l’application.

1.2. La base analytique

Un entrepôt de données est un espace centralisé, organisé pour analyser l’historique de l’organisation. Il rassemble des données provenant de plusieurs sources, conserve leur contexte et les transforme dans un format plus simple à interroger.

Système But principal Exemple de question
Base opérationnelle (OLTP) Enregistrer les événements courants « Quel est le statut de la commande 1524 ? »
Entrepôt analytique (OLAP) Comparer, agréger et suivre l’historique « Comment les ventes ont-elles évolué par région ? »

Les deux systèmes sont complémentaires. L’entrepôt n’a pas pour objectif de remplacer l’application métier.

1.3. Entrepôt, lac et datamart

  • Un data warehouse contient des données structurées, préparées et gouvernées pour l’analyse.
  • Un data lake peut stocker des données brutes de formats variés (fichiers, textes, événements) avant leur usage ; il demande des règles claires pour rester compréhensible.
  • Un datamart est une partie orientée vers un besoin ou un service, par exemple un datamart des ventes ou des ressources humaines.
AvertissementUn entrepôt ne corrige pas une mauvaise question

Centraliser beaucoup de données ne suffit pas. Il faut définir le vocabulaire métier, les unités, la fréquence de mise à jour et les indicateurs attendus. Sinon, on obtient plusieurs chiffres différents pour un même « chiffre d’affaires ».

2. Le modèle en étoile

Le modèle en étoile est une organisation pédagogique et professionnelle très fréquente pour les données analytiques. Il place une table de faits au centre et des tables de dimensions autour.

2.1. La table de faits

Une table de faits contient les événements mesurables : ventes, livraisons, appels ou visites. Elle comprend généralement :

  • des clés vers les dimensions (client_id, produit_id, date_id, magasin_id) ;
  • des mesures numériques (quantite, montant, remise) ;
  • une ligne par événement selon un niveau de détail défini.

Le grain est la phrase qui précise ce que représente une ligne. Par exemple : « une ligne représente un produit d’une commande, dans un magasin, à une date donnée ». Le grain doit être défini avant de choisir les mesures.

2.2. Les tables de dimensions

Une dimension décrit le contexte d’un fait :

  • dim_date : jour, mois, trimestre, année ;
  • dim_produit : produit, catégorie, marque ;
  • dim_client : ville, région, segment ;
  • dim_magasin : magasin, ville, zone.

Les dimensions contiennent les attributs utilisés pour filtrer, regrouper et expliquer les mesures. Elles sont souvent dénormalisées pour rendre l’exploration plus simple.

                         dim_date
                            |
dim_client ---- fact_ventes ---- dim_produit
                            |
                       dim_magasin

Le montant net peut être calculé par :

\[ \text{montant\_net} =\text{quantité}\times\text{prix unitaire}-\text{remise}. \]

Un modèle en étoile ne dicte pas un seul outil : il peut être utilisé dans une base SQL, un fichier analytique ou un modèle Power BI.

NoteLe rôle de la dimension Date

Même si la source contient déjà une date, une dimension Date facilite les regroupements par mois, trimestre, semaine ou jour ouvré. Elle permet aussi de définir clairement les périodes comparées.

3. Les mesures et les indicateurs

Une mesure additive peut être additionnée sur toutes les dimensions, comme le nombre d’articles ou le montant des ventes. Une mesure semi-additive, comme un stock de fin de journée, peut être additionnée par produit mais pas dans le temps. Une mesure non additive, comme un taux ou une moyenne, doit être recalculée à partir de ses éléments plutôt que sommée.

Exemple : si une région a 10 commandes et une autre 2 commandes, la moyenne globale ne doit pas être calculée comme la moyenne des deux moyennes si les effectifs sont différents. Il faut utiliser :

\[ \text{moyenne globale} = \frac{\text{total des montants}}{\text{nombre total de commandes}}. \]

Les noms des indicateurs doivent préciser leur définition. « Ventes » peut signifier chiffre d’affaires brut, chiffre d’affaires net, commandes payées ou unités vendues. Dans un dictionnaire métier, on documente la formule, l’unité, la période et les filtres.

4. Le flux ETL/ELT

Les données passent généralement par un flux en plusieurs étapes :

  1. Extract (extraire) : lire les sources opérationnelles, fichiers ou API ;
  2. Transform (transformer) : convertir les dates, harmoniser les unités, dédupliquer, contrôler les valeurs et calculer les champs dérivés ;
  3. Load (charger) : déposer les données préparées dans les tables de l’entrepôt.

Dans une approche ELT, on charge d’abord les données dans une plateforme capable de les traiter, puis on réalise les transformations à l’intérieur de cette plateforme. Les deux approches poursuivent le même but : rendre les données fiables et exploitables.

Un chargement quotidien doit pouvoir répondre à quatre questions simples : quelles sources ont été lues ? combien de lignes ont été reçues ? combien ont été rejetées ? quand le chargement s’est-il terminé ?

ImportantQualité et traçabilité

Conservez les données sources ou un journal de chargement, le nombre de lignes avant et après transformation, les erreurs détectées et la date de mise à jour. Ces informations permettent de comprendre pourquoi un indicateur a changé.

5. Gouvernance et sécurité, sans complexité inutile

La gouvernance désigne les règles qui rendent les données compréhensibles, accessibles aux bonnes personnes et utilisées de manière responsable. Pour commencer, un projet peut mettre en place :

  • un dictionnaire des tables et des indicateurs ;
  • un responsable pour chaque donnée importante ;
  • des règles de qualité (unicité d’un identifiant, prix positif, date obligatoire) ;
  • des droits d’accès adaptés, notamment pour les données personnelles ;
  • une fréquence de mise à jour annoncée.

Un tableau de bord ne devrait pas exposer inutilement des noms, numéros de téléphone ou adresses. On peut agréger les résultats, masquer les colonnes sensibles et limiter les accès selon le rôle de l’utilisateur.

Exercices

NoteConsigne

Les exercices vérifient la compréhension et peuvent être résolus sans ordinateur. Les calculs sont volontairement courts.

Exercice 1 (OLTP ou OLAP ?) Indiquez si la question relève plutôt d’un système opérationnel ou analytique :

  1. Modifier l’adresse d’un client.
  2. Comparer les ventes des quatre derniers trimestres par région.
  3. Vérifier si une commande est payée.
  4. Calculer la médiane des délais de livraison de l’année.
AstuceSolution de l’exercice Exercice 1
  1. OLTP ; b. OLAP ; c. OLTP ; d. OLAP.

Exercice 2 (Identifier le grain) Une table fact_ventes contient une ligne par produit présent dans une commande. Formulez le grain avec une phrase et expliquez pourquoi une commande de trois produits peut produire trois lignes.

AstuceSolution de l’exercice Exercice 2

Le grain est : une ligne représente un produit d’une commande. Une commande contenant trois produits possède donc trois lignes de détail, même si elle n’a qu’un seul numéro de commande.

Exercice 3 (Faits ou dimensions) Classez les éléments suivants : montant_net, categorie, annee, quantite, ville_client, prix_unitaire.

AstuceSolution de l’exercice Exercice 3

Faits ou mesures : montant_net, quantite, prix_unitaire. Dimensions ou attributs de dimensions : categorie, annee, ville_client.

Exercice 4 (Calculer une mesure) Une ligne indique 3 articles à 120 MAD chacun et une remise de 40 MAD. Calculez le montant net. Une deuxième ligne indique 2 articles à 80 MAD sans remise. Quel est le montant total des deux lignes ?

AstuceSolution de l’exercice Exercice 4

Première ligne : \(3\times120-40=\textbf{320}\) MAD. Deuxième ligne : \(2\times80=\textbf{160}\) MAD. Total : \(320+160=\textbf{480}\) MAD.

Exercice 5 (Mesure additive ou non ?) Indiquez si l’on peut additionner directement la mesure sur les périodes suivantes :

  1. Le montant de ventes.
  2. Le stock disponible à la fin de chaque jour.
  3. Un taux de conversion en pourcentage.
AstuceSolution de l’exercice Exercice 5
  1. Le montant de ventes est additif.
  2. Le stock de fin de journée est semi-additif : on peut comparer ou prendre le dernier stock, mais le sommer sur les jours n’a généralement pas de sens.
  3. Un taux est non additif : il faut recalculer le taux à partir des numérateurs et dénominateurs.

Exercice 6 (Comprendre ETL) Remettez dans l’ordre : charger les données préparées, extraire un fichier CSV, convertir les dates et contrôler les prix négatifs.

AstuceSolution de l’exercice Exercice 6
  1. Extraire le fichier CSV.
  2. Convertir les dates et contrôler les prix négatifs.
  3. Charger les données préparées.

Exercice 7 (Moyenne globale) La région A compte 10 commandes de 100 MAD en moyenne. La région B compte 2 commandes de 300 MAD en moyenne.

  1. Quel est le total estimé de chaque région ?
  2. Calculez la moyenne globale.
  3. Pourquoi la moyenne des deux moyennes, 200 MAD, est-elle incorrecte ?
AstuceSolution de l’exercice Exercice 7
  1. A : \(10\times100=\textbf{1\,000}\) MAD ; B : \(2\times300=\textbf{600}\) MAD.
  2. Moyenne globale : \((1000+600)/(10+2)=1600/12=\textbf{133,33}\) MAD environ.
  3. Les régions n’ont pas le même nombre de commandes ; la moyenne de 200 MAD donne le même poids aux deux groupes.

Exercice 8 (Qualité et sécurité) Proposez une règle de qualité et une mesure de protection pour chacune des situations :

  1. La colonne prix contient parfois des valeurs négatives.
  2. Un tableau de bord doit être partagé avec des responsables régionaux.
AstuceSolution de l’exercice Exercice 8
  1. Règle : prix >= 0, avec rejet ou examen des exceptions.
  2. Protection : filtrer les données selon la région de l’utilisateur et ne partager que les colonnes nécessaires ; les noms ou coordonnées personnelles peuvent être masqués.
